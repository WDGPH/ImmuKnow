# Contributor guidance

Read [README.md](README.md), the [contributing guide](docs/developer_guide/contributing.md), and the relevant user guide before changing a public workflow. Follow the user's instructions when they differ from repository guidance.

ImmuKnow Core is a standalone Rust application. It prepares facts from an input CSV, uses the explicit template assignments, compiles notices with embedded Typst, records findings, optionally creates separate encrypted copies, and assembles notice and review bundles. Upstream systems assess immunization status; Typst templates own wording and presentation. Core ships shared Typst resources and schemas. Project settings, reference lists and starter notices belong in ImmuKnow-Template; Core keeps only small fictional configurations in tests/fixtures/config.

Keep the workflow linear and preserve source-row identity from input through the final report. Retain usable original PDFs when a notice or its evidence fails. Failures and warnings remain distinct: warnings are eligible for sending under the effective policy, while readable originals with failed checks go to review bundles. A withheld row is not bundled. Never persist derived passwords; encryption uses separate AES-256 revision 6 copies, checks the constructed encryption settings and propagates write failures. Release tests verify password access and content round trips; production does not reopen newly written copies to repeat those tests.

Use one saved run record and its escaped HTML view. Preserve observed checks separately from effective policy results, per-row artifact outcomes and bundle membership. Account for readable source rows even when setup or input processing fails. Expected row failures should not stop later independent rows. Keep the `.incomplete` staging convention, unique run and bundle-attempt directories, and the per-run operating-system lock for saved-run changes. Fixed page counts do not add padding. Do not add repeat visual or page-by-page comparisons, repeated artifact validation, review sheets, stamping, or warning-waiver machinery.

Bundle assembly lives in `src/bundles.rs`. Resource export code lives in `src/resources.rs`; generic project setup and
sample-path handling live in `src/project.rs`; shared schemas and the Typst library live in `resources/`. QR plugin source lives in `typst-plugins/qr/`; user projects supply their own templates and configuration. Do not write into an installed executable's resource tree. Keep Typst imports within the supplied project; ambient package downloads are not supported. The unversioned rendering schemas and `tests/fixtures/render-contract.json` define the shared evidence contract. Keep test data and committed assets fictional.

Run focused checks appropriate to the change, then applicable checks from the [testing guide](docs/developer_guide/testing.md). Lock dependencies with `Cargo.lock`. Describe behavior, verification and material limitations in pull requests; do not add dated development journals. Keep documentation current and link to the owning guide rather than duplicating contracts.
